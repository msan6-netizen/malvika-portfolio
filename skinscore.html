SkinScore AI

A personalized skincare analysis platform. Users build a skin profile through an adaptive, AI-driven interview, then scan a product and get an explainable verdict scored against their skin, not a generic hazard rating.

The problem

Existing scanners like Yuka run an ingredient-hazard scan, but miss the two things that actually matter: efficacy (a "vitamin C serum" may not contain the active at an effective concentration) and personal fit (a great product for one person can be wrong for another's skin, medications, or sensitivities). SkinScore answers "is this right for you, and will it do what it claims?"

What it does

Adaptive AI interview

Instead of a fixed form, an LLM asks the next-most-informative question across dermatological "skin pillars" until it has enough signal to build a structured profile.

Three-score analysis

Personal Fit (safe/effective for this user), Ingredient Science (evidence-backed formulation quality), and Real Users (outcomes from similar people).

9-dimension risk profile

Irritation, comedogenic, fragrance, preservative, pH, stability, conflict, and more, with a floor rule so one high risk can't be averaged away.

Impact

Reasoned estimate: verifying one product's claims by hand means cross-referencing every ingredient across scattered sources, easily 10 to 15 minutes, so most people skip it and trust the label. SkinScore turns that into an instant, sourced BUY / CAUTION / SKIP scored against the individual, making a decision that was effectively unanswerable both quick and consistent.

How it's built

React SPA frontend, Supabase (Postgres + Deno serverless edge functions) backend, and a Claude-powered LLM layer grounded by an evidence-retrieval pipeline (curated DB + live PubMed lookup) over a dermatological knowledge base.

React SPA (Vite) | supabase-js (auth + function calls) v Supabase Edge Functions (Deno) |- interview-start / next / complete adaptive interview + profile synthesis (Claude) |- product-scan INCI ingredient parsing + product matching |- product-score core engine: 3 scores + 9-dim risk + claim verification |- ingredient-lookup evidence: DB -> fuzzy match -> PubMed + Claude v PostgreSQL (profiles, products, ingredient_evidence, reviews - all RLS-scoped)

The product decisions that matter

  • Deterministic scoring, LLM at the edges. The scoring math is deterministic, so identical inputs return identical, explainable, reproducible verdicts. LLMs handle the fuzzy work (interview, parsing, enrichment) around the core, never the score itself. This is what makes it consistent where a raw chatbot isn't.
  • Evidence over assertion. Every factual claim is grounded in a curated knowledge base (PubMed / CIR / SCCS) with citations, rather than a one-off LLM answer.
  • A floor rule for safety. A single high-risk dimension can't be averaged away into a friendly overall score.
  • Honest build scope. The frontend was scaffolded with an AI app-builder and customized; the backend, the scoring engine, the adaptive interview, the evidence pipeline, and the data model, is the hand-architected core, built with Claude as an engineering collaborator.
